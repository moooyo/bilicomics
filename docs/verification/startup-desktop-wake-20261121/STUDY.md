# What wakes the first desktop startup turn?

## Question and scope

The [previous ordinary desktop trace](../startup-direct-png-20261121/phase-profile.md) showed loading feedback roughly 64 ms before the state worker was queued. It did not say which callback entered the UI driver. First identify the actual callback on the unmodified desktop software backend. Then test whether **one additional UI turn after an accepted, full-window software submission** can advance the first complete Shelf without losing startup feedback. Neither the old 80 ms maintenance period nor a difference between two stage timestamps is an estimate of product savings.

This is an isolated `test-env` Linux/X11 study, not a Kindle run. The shipping Slint 1.17.1 software renderer does not supply an application-level post-present notification. A Winit `RedrawRequested` filter runs *before* drawing; a successful draw may also have no drawable surface or damage. Even `AfterRendering` on renderers that support it is a back-buffer notification, not a presentation receipt. See the [rendering-state contract](https://docs.rs/slint/1.17.1/slint/enum.RenderingState.html) and the [pinned software backend source](https://docs.rs/crate/i-slint-backend-winit/1.17.1/source/renderer/sw.rs). Do not implement this by shortening the recurring timer, requesting an immediate blind wake after `show()`, suppressing a loading frame, or waking on an unchecked redraw. Native first-SEND admission, cover preparation, continuation, suspension, error handling and the existing 80 ms fallback are out of scope for behavioral changes.

## Controls and intervention

- **A0 (stock, untimed):** `9175002` plus the three retained catalog inputs and common, one-time provenance in `src/main.rs`. `driver_first_entry` names the first invocation. `ui_worker_gate` separately identifies the turn that crossed the initial UI yield, whether it won worker admission, and the renderer-notifier state. A coalesced `runtime_wakeup` is not proof of a render-triggered wake. Run a natural, populated ordinary Shelf qualification on A0; do not use its times as the control arm.
- **A (observe) and B (wake):** use the **same private research executable**, compiled from A0 with a private copy of the exact locked Winit backend and its license. Same command line, renderer, tracing and seed. Both register the same per-window one-shot probe and schedule the same 16 ms follow-up after the first successful full-surface `present_with_damage`. This grace is a scheduling choice, not a hardware refresh period or a claim that someone saw the screen. A only observes; B may enter the normal driver once on that follow-up if it is still waiting, live and unsuspended. A late or unavailable hook must leave the existing fallback in charge. Neither the X11 observer nor its polling schedules the application.
- Neither the research backend fork nor its mode switch is a shipping dependency. A positive desktop result would justify a supported per-window post-submit capability; it would not justify a blind one-shot timer, a permanent third-party fork for this result alone, or a Kindle rollout. Only common optional diagnostics are eligible to remain in product source.

## Admission and decision (before timing)

1. Rebuild the [ordinary, offline, synthetic account fixture](../startup-direct-png-20261121/FIXTURE.md) and its references from scratch. No real account, login, external network, installed data or device. Prove the A0 reference has all ten distinct page-one cover codes; an identically populated signed-out control must display none. Qualify natural A0, observe and wake launches independently against full-window and logical references. Keep receipts and do not silently replace a failed attempt.
2. Verify software startup tests, including the original worker gates and cancellation. In separate non-timing controlled PW6 and Scribe desktop runs check initial and final pixels, changing activity during slow preparation, and absence of ready on failure. The first UI turn must still yield before consuming a result. Fallback, late callbacks and guards are correctness requirements, not timing samples.
3. Use a fresh private Xvfb and independent copy of the closed seed for each natural launch. Use the existing process-local fixed realtime shim symmetrically for wall-clock pixels; keep real `CLOCK_MONOTONIC` and thread CPU clocks. Exclude one warmup of each arm; retain six AB/BA alternating pairs with no replacement or extension. No synthetic delay, forced startup capture or diagnostic render is allowed in those launches.
4. Require the same PID and window for loading-title and initial activity-region observations; **both actual read returns must precede the earliest worker admission or queue**. Neither crop alone proves a complete startup frame. Require a later full RGB match to the frozen Shelf, a confirmation and an independent final logical match. Bracket the first Shelf from the last nonmatch request start to the first full match return, relative to each process's own entry. An uncertain ordering remains in the table and cannot count as a successful safety gate.
5. Attribute any effect using real full-submit, subsequent UI-turn, first-driver, worker-gate, queue, software-ready and X11 observation clocks. Distinguish source classification from elapsed time, backend submission from visibility, and CPU costs from end-to-end time. Require all feedback/behavior checks, B's first-Shelf upper bound **strictly below** A's lower bound in at least **five of six** pairs, and negative median paired first-observation changes in **both** order groups. Otherwise the experimental desktop improvement is not demonstrated. Do not mix in earlier PNG, demo, stock-qualification or Kindle timings.
