# Desktop wake: frozen ordinary Shelf presentation protocol

The non-timed stock control A0 includes the common first-driver/source diagnostics and has no private renderer hook. The two formal arms deliberately execute **one identical research ELF** at `/work/research`, with identical executable path and arguments apart from the isolated case output paths. Only `BILICOMICS_DESKTOP_PRESENT_PROBE=observe` (A) or `wake` (B) selects the study behavior. Both arms instrument the same successful software full-window submit and schedule the same deferred 16 ms turn. A observes only; B attempts a drive only when the guarded desktop bootstrap still needs it. Neither arm is the previous direct-PNG candidate. No previous application binary, ordinary Shelf reference, profile, or timing measurement is an input.

1. Use a fresh 0700 private workspace on `test-env`, bound as `/work` using a fresh PID, mount, and loopback-only network namespace. Compile and qualify the existing [application-only fixed realtime shim](../startup-direct-png-20261121/check_wall.py) there. The observer, Xvfb, shell and helper are not preloaded; application and observer monotonic clocks remain real. Bind each release copy to its current source with `cmp` and each running PID to the selected copy via `/proc/PID/exe`. Use `wake_pairs.py` for every launcher invocation, including the subprocess of each new Xvfb. Do not edit the previous study's observer.
2. Follow the [ordinary qualification protocol](../startup-direct-png-20261121/PROTOCOL.md). Reuse its scripts, production PNG writer, in-process mock validation helper, non-demo/offline flags, ten unique synthetic cover markers, actual mapped Scribe window and fully independent logical final comparison. `/work/direct-png-fixture` is the helper's required internal subdirectory in this **new** private workspace, not a reference to an existing seed or candidate. Run `bootstrap` with `/work/stock` in an empty data directory and `make-seed`; subsequently use `reference`, `negative`, `check-stock`, `check-a`, `check-b`, then `qualification-summary`. The same catalog and covers without a session must show the actual empty-control login prompt and none of the ten positive cover codes. Rebuild both full-window and logical positive references from the qualified A0. `check-stock` separately measures natural loading feedback and callback provenance in the populated stock Shelf: no mode is supplied and neither research event may be present. The formal qualifications and samples use a fresh per-process environment; read only the mode key from `/proc/PID/environ` and verify `/proc/PID/exe`. Arm selection never depends on the executable filename or argv. Empty, signed-out and populated setup launches are not timing samples.
3. Before any formal launch, obtain explicit admission. Keep the two excluded warmups and exactly six paired AB/BA launches: `a00 b00 a01 b01 b02 a02 a03 b03 b04 a04 a05 b05 b06 a06`. Every case gets its own private profile copy, home and fresh Xvfb, with the same production-encoded assets; use `--offline --screen shelf --device scribe`, no demo, artificial delay or forced startup snapshot. No discarded cases, substitutions or extension. Keep and report any failure. A first observation must be an exact match of **all** real RGB pixels of the same owned window, followed by another match after at least 80 ms. A corner cannot pass. Record the conservative `[last nonmatch read start, first full match read end]` relative to the application entry. Check the independent end-of-run logical image, all 10 marker codes, page 1/2, normal Ready, two attachment batches, ten residents and 5,324,800 bytes.
4. The visible loading title **and** initial activity region must be observed in the exact same window. The adapter records the positive intervals of the existing reads, without adding any X11 round-trip or product delay. The later of their two XGetImage return times must be at or before the actual `workers_started` producer timestamp for the strongest pre-worker evidence, with the `font_worker_queued` and `state_worker_queued` boundaries separately available. Also report whether both returns precede the state-worker queue and, separately, its result. An observed loading frame before preparation *completion* is not proof of loading before admission. Do not use notifier registration, AfterRendering, a requested redraw, a clock reconstructed from a timeout, or `ui_ready` in place of pixels. A failed or ambiguous pre-worker claim stays with the case and cannot be fixed by retrying or silently loosening the rule.
5. Bind `driver_first_entry` and `ui_worker_gate` to the process UI thread, recording each callback source, registration result, the presence/absence of a real first-render event and `workers_admitted_by_ui`. Distinguish the `workers_started` lifecycle observation from its later performance-record write, the two real queue markers, worker beginnings, and the UI gate record written **after** admission. A runtime callback is not proof of which subsystem requested the wake; no render-to-pixel implication is made. Report per-case source and timing as well as end-to-end brackets. Adopt only with all correctness/visible-feedback gates, at least five of six pairs with B upper strictly before A lower, and earlier paired first-match medians in both AB and BA orders. Otherwise keep A. None of these X11 measurements is a Kindle driver, physical panel or live-account measurement.

6. Require the research `desktop_software_full_submit` and `desktop_post_submit_turn` diagnostics at their actual UI-thread envelope timestamps. The former records mode, full-buffer dimensions and UI-thread provenance. The latter records mode, proposed delay, whether the workers had previously started, existing window/boot/suspend/quit/cancellation state, driver availability and whether the callback will drive. Check the subsequent real driver and admission owner rather than treating `will_drive` as proof. A successful software submit is not an external X11 observation. Both arms have the same sensors; A0 is deliberately outside these pairs.

### Environment-check admission amendment (before formal measurement)

The first untimed `check-a` stopped before any X11 measurement or trace: a `/proc/PID/environ` read immediately after `Popen` provided no mode. In a separate non-window `research --help` diagnosis, all three immediate reads returned zero bytes and the executable exited normally; the same method could already see the injected key for a small `sleep` child. A zero-byte read does not prove that a variable is absent. Preserve the setup attempt, not a timing sample. Keep the arguments, binaries, mode, scheduler and qualified pixel measurements unchanged. For completed-window cases check `/proc/PID/exe` on launch, then make one nonblocking, nonempty live environment read after the X11 observations and before final exit; retain only the result for the specified mode key. Require the matching mode within both actual UI-thread telemetry events for the formal application. Check the separately qualified stock likewise without a mode or either event. No formal case was started or replaced by this amendment.

## Restricted replay

`python3 -B wake_replay.py /work/trial /work/export` consumes the single complete formal trial, not qualification launches. It reuses the ordinary Shelf minimizer and adds only the allowlisted callback sources, booleans, producer/queue/worker monotonic stamps, and the initial activity sample interval. The raw input, reduced input and independently unpacked archive must yield the same pair tables, stage-cost summary and `audit_wake_sources.py` output. The public receipt excludes application data paths, images, full UI models, external requests, private accounts and logs. A missing or ambiguous external observation remains visible in the report; no successful CPU or timing projection supersedes the software correctness gates.
