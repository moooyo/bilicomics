# Research-only application probe

Apply [the patch](app-submit-probe.patch) only to the private research copy of `src/main.rs` from the common-diagnostics control. Use the paired study's patched Winit software renderer and Slint's `slint/unstable-winit-030` feature. The ordinary source and Cargo manifest do not depend on this private callback. The stock common control is a separate, untimed qualification. The formal arms use **one research ELF**, setting `BILICOMICS_DESKTOP_PRESENT_PROBE` to `observe` or `wake` only for the application process. Do not select either mode on a Kindle.

Both modes install the same window-bound, one-shot observer after show and size configuration. Both wait for a successful *full software submission*, record its dimensions and schedule one Slint timer with the same 16 ms interval. This is not a timer from process entry and does not establish that the screen pixels were observed. On expiry both modes attempt the same nonblocking driver borrow and inspect the same guards. Only `wake` may immediately call the original driver with source `desktop_startup_fallback`. A busy borrow or failed guard skips that call without retry. Window and driver references are weak. The existing maintenance timer, bootstrap yield, cancellation, and single worker admission remain unchanged.

- `desktop_software_full_submit`: `mode`, physical buffer `width` and `height`, and `ui_thread`. It records the successful callback, not a standard `AfterRendering` notification or an optical observation.
- `desktop_post_submit_turn`: `mode`, configured `delay_ms`, `ui_thread`, `window_alive`, `booting`, `workers_started_before`, `suspended`, `quitting`, `cancelled`, `driver_available`, `will_drive`. The delay is a request, not the measured interval. `will_drive` is recorded **before** the call; confirm the actual callback and admission from `driver_first_entry`, `ui_worker_gate` and `workers_started`.
- The `ui_thread` flag compares the callback thread with the registration thread. Also check the common trace's thread ID and first-frame pixels independently. There are no additional lifecycle events, backdated samples or off-thread UI calls.

The focused `--bin bilicomics` test is `trace_tests::desktop_post_submit_is_wake_only_and_fails_closed_for_each_guard`. The existing `startup_admission::tests::early_and_fallback_admission_start_exactly_once` and `startup_admission::tests::early_admission_does_not_remove_the_original_ui_yield` exercise the downstream worker gate. Their presence is not a claim that the real software presentation hook fired; that requires separate fixture and window evidence.
