# Native startup display poll: three fixed visits

**Question:** When the existing display helper calls `poll`, how many calls and how much wall time occur with its stdout pipe descriptor still selected, versus after it has observed EOF and supplied `fd = -1`? This is a descriptive engineering baseline, not an optimization or A/B. The [earlier study](../startup-display-sampling-20261122/README.md) measured the parent interval alone; do not pool the visits, reconstruct a missing child from those older data, or invoke the helper directly over SSH.

## Frozen protocol

- Predeclare **three** single-arm visits in ordinal order. Include the first; there are no warmup exclusions, retries, substitutions, added visits or stops based on an observed duration or source. Keep the same qualified engineering ELF, unchanged approved launcher/document source, worker, stage layout, fresh demo seed and native card. Only the staged **startup** call to `capture_native_epdc_mode` receives `BILICOMICS_DISPLAY_POLL_RUN=<this run>`. The helper remains `--capture-native-display --kindle --device scribe`; no wake, lifecycle, performance, strace or previous display-cost collector is enabled. The main application uses `--kindle --device scribe --data-dir <stage>/data --demo --offline --shelf-render-trace <stage>/data/<run>.jsonl --exit-after-ms 2500`.
- Qualify the exact three staged archives, argv/guards/cleanup, sidecar producer, strict reader, stock stdout parser, original watchdog/revocation/retirement, expected refusals, and isolated Scribe/PW6 paths on `test-env` **before** any lease. A host getter fixture is not real LIPC or a physical panel; QEMU user mode without an owned native snapshot must refuse. Preserve the original two-second watchdog, deadlines, 10 ms maximum `poll` slice, 100 ms periodic permit-check schedule, flags, call ordering, sleep coverage, child management and error handling. A receipt does not override a failure or set another timeout.
- On each actual visit acquire a new exact lease, click the single positively recognized ordinary native Library card once, and allow a normal natural exit. Bind the primary card-release bracket to the **first populated ordinary Shelf renderer return** on the same `CLOCK_MONOTONIC` and UI PID; placeholders are allowed. Accepted SEND and same-marker driver completion are separate optional endpoints, never evidence of optical completion or clickability.
- The startup-only helper writes at most one fresh `<run>.display-poll.json`. The narrow collector reads only that file after independently verified natural retirement and never reads generic logs or raw display values. It checks the qualified writer's clock/run/boot, distinct helper/reader/supervisor processes versus the independently witnessed UI PID, and the existing permission-derived ancestry/birth evidence. An exact device-side allowlist rejects extra bytes or unknown fields before transmission. This does not claim an independent host witness for the capture helper PID. Keep raw IDs, absolute clocks and paths private.
- Restore the original launcher and native tab/pointer, remove only admitted stage files, close the connections and return the exact owned lease before any timing calculation. Do not reserve or queue when the device is busy. On a failed/ambiguous dispatch, scope mismatch, missing eligible evidence or recovery requirement, halt; recover only the original batch if ownership is established. Do not continue to fill three slots. Unknown release is not a qualified missing-value receipt.

## Partition and analysis

The two new fields are appended to the unchanged 18 buckets of the new `kindle-startup-display-poll-v1` record. **Exactly one** is selected by the descriptor on the original `pollfd` for each actual `poll` call. `command_poll_stdout_open` means `fd >= 0` (the helper had not marked stdout closed when calling poll); `command_poll_after_eof` means the helper had observed EOF and passed `fd = -1`. It does not establish that the child already exited, that a wake was lost, that a call lasted the full 10 ms, or that its duration equals service/device work. Scheduling, interrupts and original timeout behavior remain possible. There are no new poll calls or child-specific clock reads. Both updates reuse the parent observation's exact timestamps.

For **each visit**, first require `open.count + after_eof.count == command_poll.count` and `open.elapsed_ns + after_eof.elapsed_ns == command_poll.elapsed_ns`, exactly in integers. Retain the original `commands_run` decomposition: subtract `command_poll` once as before, **never** its two children in addition. Report the parent and both child counts and nanoseconds; for each child also report `share_of_poll_count` and `share_of_poll_elapsed` as ratios in `[0,1]`. A zero denominator means `null`, not a zero share. The exact numerators and denominator remain available for each visit. No post-hoc cutoff for the two-second watchdog and no comparison to optical response.

The automatic path still performs five property reads and two metadata observations. The fixed path naturally performs three property reads and two metadata observations. Both are eligible: label each visit and count them separately; do not force orientation, conflate the branches, or add a fourth visit. Only **three valid visits on the same branch** get a median for that branch. Compute medians of per-visit counts, nanoseconds and shares; never form a share by dividing unrelated medians or add them to reconstruct a timeline. An undefined per-visit share means no three-visit median for that share. For mixed or incomplete branches keep the individual observations and denominators, no pooled median. Never interpret these classifications as removable time or an effect on startup.
