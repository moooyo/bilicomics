# Full product poll-partition qualification

This off-device functional check runs the new x86-64 Kindle-feature `bilicomics` executable in a private `test-env` mount, network and PID namespace. The stock shell grants and withdraws its own permission; the original process ancestry checks, two-second budgets, parser, group cleanup, `read`, `poll` and `try_wait` remain in use. Do not run the inner namespace script directly, direct-invoke the helper, or treat this as device, Shelf or firmware timing evidence.

Use a fresh root-owned `0700` workspace under `/var/tmp/bilicomics-display-poll-product-*` and the separate qualified `bilicomics-display-poll-build-*` output. Prepare these files in the workspace before running the executable:

- `inputs/run.sh`, `inputs/product_run.py` and `inputs/getter.py`: the files in this directory.
- `inputs/inside.sh`, `inputs/fb_read.c`, `inputs/usleep.c` and `inputs/stock-getter.py`: unmodified [previous hardware fixture](../../startup-display-sampling-20261122/product_fixture) files; name its `getter.py` copy `stock-getter.py`. Compile the framebuffer shim and real `usleep` in the isolated Ubuntu userspace as documented there.
- `inputs/stock-launch.sh`: the original `bilicomics/launch.sh` member of the approved installation archive, verified byte-for-byte against the frozen source.
- `inputs/studies/`: retain the dated directory structure for **both** `collect_display.py` files, the previous study's `host_bench.py`, `startup-prepared-handoff-20261122/handoff_collect.py`, and `startup-interactive-kindle-20261121/{shelf_operator,log_bounds}.py`. The new collector must be the same one frozen for the new three-visit controller.
- `reports/`: initially empty and private. Run `bash "$workspace/inputs/run.sh" "$workspace" "$build" r1` on `test-env`. The outer gate requires the new source schema/selector/suffix, the full isolated product build and both missing-permission refusals. Only the validated ELF is streamed into the private `/mnt` tmpfs.

For both Scribe (automatic) and PW6 (fixed), the simulated mode getter briefly leaves stdout open, writes its valid response, closes its own stdout fd, and stays alive briefly before exiting. It does **not** intercept `poll`, fake its result, alter the descriptor or add any timing calls to the product. The complete helper must return the original ready frame, perform both metadata observations and produce exactly one run-named poll sidecar. Real getter ancestry must match the sidecar. The new collector reads, decodes and projects its exact product bytes. In each case both poll states must appear; their counts and nanoseconds must independently sum **exactly** to the original `command_poll` count and elapsed time. These totals cover the whole capture, not an attribution to one getter.

Three controls are also required: normal success with the selector absent; a first getter with its live permission withdrawn; and a first getter exceeding the original watchdog/budget. No failed or unselected case may publish a sidecar or leak an owned process. Only the aggregate `host-product-qualification.json` is published. Raw identities, timings and per-case markers stay private; the measured host durations are not a device baseline, a saving or a product change.
