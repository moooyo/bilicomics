# Reversible native Library render diagnostic

This is a research-only route for the **existing** `BiliComics for Kindle` card on the qualified Scribe (firmware `5.19.5`). It requires explicit authorization to switch the installed launcher temporarily. It is not the stock launch path, a package installer, a substitute lease manager, or evidence that the Shelf accepts touch. There is no filter tap or optical assertion. No script here opens a connection, acquires a host lease, invokes a native handler, or signals an application process.

The one native activation is the separately qualified device-generated Library click. Its card-release bracket is the timing origin. The primary endpoint is the first qualifying Shelf renderer return; accepted submission and same-marker driver completion are optional supplemental device events. None is stock, optical, cover-complete, or interactive startup latency. Report the extra entry shell, single-use pick directory, timestamp record, diagnostic observation, isolated demo state, and any observer overhead as such. `--exit-after-ms 2500` starts only after readiness; it is an exit convenience, not a startup deadline or completion receipt. A failure to reach a qualifying frame needs the established managed recovery and must not be reported as a successful sample.

## Prepare before the lease

Run the filesystem rehearsal on `test-env` in an isolated workspace. It compiles the helper for the host, substitutes an isolated filesystem and simulated Kindle inventory, and does not reach the device. It does not qualify VFAT. In the same source workspace, build the new Kindle ARM application with the Shelf render diagnostic. Use its same-build JPEG worker, or the already qualified identical worker when unchanged. Point `--shipping-launcher` and `--document-launcher` at the exact production source from the retained installed package. The application version, hash, and production data are not inferred from the current checkout.

```bash
python3 -IB "$route/test_route.py"
zig cc -target arm-linux-musleabihf -std=c11 -O2 -Wall -Wextra -Werror -static \
  "$route/route-fs.c" -o "$scratch/route-fs"
python3 -IB "$route/prepare_route.py" --run "$run" \
  --application "$candidate" --worker "$worker" --route-fs "$scratch/route-fs" \
  --shipping-launcher "$known_installed_launch_source" \
  --document-launcher "$known_installed_document_source" --output "$scratch/stage"
```

Use the fresh host lease's `bili-shelf-<32 lowercase hexadecimal digits>` run ID. `--output` must name an absent directory. The resulting private stage contains:

| Files | Role |
| --- | --- |
| `run-id`, `switch.sh`, `route-fs`, `cleanup-assets` | Exact run binding, management script, non-hot-path filesystem guard, and fixed bundled-demo asset roster. |
| `shipping-launcher.sh`, `document-launcher.sh` | Independent byte-for-byte production comparison sources. They are never published under production names. |
| `entry.sh`, `entry-ready.sh` | Comparison copy and movable copy of the short diagnostic shim. |
| `launch.sh`, `app/bilicomics`, `app/kindle-jpeg-worker` | Isolated launcher and executables. The shipping script differs by **one** application argv insertion; the helper invocations and Library wait semantics are unchanged. |
| `data/device-profile`, `data/device-allowlist`, `data/demo/state.sqlite3` | Separate accepted configuration and schema-zero synthetic database containing only the `design-demo` default Shelf preference. The application creates the remaining schema and bundled demo data. There is no `--screen` override, production account, copied content, or network request. |

The device-side coordinator creates the absent exact path `/mnt/us/$run` through its pinned leased transport and transfers only these files and directories. No symlinks, archive links, unknown entries or existing destination are permitted. Ensure `route-fs`, `app/bilicomics`, and `app/kindle-jpeg-worker` are executable; the other shell files are invoked via `sh`. Verify staged bytes against these inputs before use. Stage an optional separate card observer outside this tree. If upload or stage admission fails before running `activate`, no production path has been touched. The coordinator may clean its confirmed, explicitly enumerated upload leaves and empty directories only; never run half-uploaded code or use recursive deletion on an unknown stage.

For the [paired Shelf render-order study](../../startup-shelf-ab-20261121/RUNNER.md), the comparison arm appends the single opt-in `--serial-shelf-render` after `--exit-after-ms 2500`. With no opt-in, the launcher argv is byte-for-byte unchanged. The prepared `switch.sh` verifies the one exact invocation for its own arm, not a choice between both. Use the paired series preparer for this study: the single-visit host controller normally expects the default argv; the paired preparer also binds its private process witness to the comparison argv. No mutable mode selector is installed on the device. Both arms use the same return and cleanup guards.

## One leased batch

Each management command takes the device-side nonblocking operation lock on the open production directory inode. This does not replace the exact shared host lease. It serializes cooperating route commands, not installers, queued native dispatch or other root processes. No installation, navigation rerun, asynchronous maintenance, or parallel device input may overlap the route. Use the already vetted pinned transport and existing native/owned-process guards for the whole batch. The helper is deliberately restricted to fixed directory descriptors, known file pairs, and same-volume `renameat`; it does not rely on `renameat2` support on Kindle media.

1. Run `sh /mnt/us/$run/switch.sh "$run" inspect`. On a fresh stage expect `run=$run` and `route=stock` on two lines. This is a read-only identity check, not native-restoration evidence. It requires the real lowercase document with production bytes and one exact catalog row, both established application binary sizes, the accepted profile/allowlist, and the known firmware/framebuffer geometry.
2. With native control idle, run `sh /mnt/us/$run/switch.sh "$run" activate`. It first qualifies the operation lock and cross-directory rename (including original inode, mode, size, and content) on a stage-local dummy on the same volume. If this fails, it never moves the installed launcher. It records the original and shim identities and their comparison context, parks only the original launcher as `retained-launch.sh`, and publishes the shim. The temporary gap has no `launch.sh`: make no input and do not dispatch the card until `route=armed` is verified. The indexed document, app/worker, data, and peer paths are never mutated.
3. Use exactly one intended click on the native card. The shim claims `picked` with `mkdir`, records the Library shell's PID and Linux start ticks in `picked/entry` as `<run> <pid> <ticks>` plus a newline, and `exec`s the isolated `--library` shipping path in the same process. No repeat is permitted. The candidate writes `data/$run.jsonl`. Keep the run/PID/boot evidence aligned; absence of a trace or entry is not a successful launch or a successful exit.
4. Confirm the original handler dispatched and retired, the stamped Library entry and its managed worker/application ceased, and native control returned using the coordinator's independently qualified checks. If the click may have been delivered but no pick was seen, a single idle snapshot does **not** prove the queued dispatch is gone. Resolve actual dispatch and retirement before reverting the path; a late invocation after stock restoration could otherwise open the real application. Do not retry the click or infer retirement from the timer. Use only the independently vetted native/owned-worker recovery if the normal exit fails.
5. Run `sh /mnt/us/$run/switch.sh "$run" restore`. It removes the arm gate first; a shim that may already have passed the gate is detected through its stamped PID. It refuses to move anything while that identity or a launcher lock is active or native control is not idle. Expect `route=stock`; recheck canonical launcher bytes and identity and the independent native recovery result. Collect only this run's trace and anonymous receipts, then run `sh /mnt/us/$run/switch.sh "$run" cleanup` and expect `route=removed`. The cleanup enumerates allowed contents before removing any, rejects foreign files or symlinks, and removes only named regular leaves and empty owned directories. Close the device connection and immediately release the exact host lease; analyze the evidence afterward.

## Interruption and refusal

- Manage recovery with the original lease/run/stage only. Never reactivate an interrupted run or use a new lease to relabel it. Before the journal, the production launcher is untouched. A committed journal plus stock launcher needs no move. `route=parked` means only the original was parked; `route=unarmed`, `armed` or `used` means the diagnostic shim is at the original name. After the exact dispatch/native checks, `restore` resumes from either rename boundary and refuses a missing or foreign original, even one whose bytes match but identity differs. `inspect` reports no identity when the paths are ambiguous.
- The journal requires the same device boot and exact original and comparison identities. It cannot certify media replacement, a reboot during the switch, a foreign edit, or filesystem corruption. Preserve unknown evidence and request separately authorized recovery rather than overwriting a path in any of those cases. A site that cannot qualify the preflight or same-volume rename must not use this route.
- Kindle may update the lowercase card document's modification time when it opens the card. Only this timestamp is excluded: the same device and inode, mode, size, link count, exact bytes, and unique catalog row are still required. Other file timestamps remain pinned.
- After verified restoration, cleanup ignores terminal hangup and removes runtime data before its small control-file tail. If the operation is killed, retain the restore receipt and recheck stock independently. Retry cleanup only while the intact stage can still be checked. Admission scripts may already have been removed during the tail; remove only the confirmed owned leaves left from that run and its empty directories using the prepared roster and finished evidence, or leave unknown contents sealed. Do not repeat activation or rewrite the production path for a staging-cleanup failure.
