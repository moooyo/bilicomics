# Startup cover handoff: one-factor experiment

## Question and arms

Does moving the existing straight-RGBA copy from UI attachment to the gated cover worker make the **first complete Shelf** appear earlier, rather than merely making one UI stage cheaper?

- **A:** `9175002` plus the three retained catalog-read source/test files described in the [preceding study](../../STARTUP_PRE_READY_20261121.md). A decodes into a `Vec<u8>` and copies into a Slint pixel buffer on the UI thread.
- **B:** exactly the same tree and catalog read, except for `src/app/startup.rs` and `src/app/covers.rs`. After decoding and checking the retained-byte budget, the cover worker copies into `SharedPixelBuffer<Rgba8Pixel>`; the UI constructs an `Image` from that allocation. There is no new runtime flag. A and B have separate release executables, built in the same private target using the same options.
- Do not change the 16 MiB retention limit, the 4 MiB pre-item byte check, the 4 ms attachment budget, cover order, gating, animation, route policy, observer settle, or framebuffer barriers. The Scribe fixture still needs two attachment batches (nine covers, then two); the historical 410–509 ms gaps are not an estimated speedup. The decoded and Slint allocations for one cover can coexist during the copy. A retained-byte limit is not a measurement of peak RSS.

## Checks and decision

1. On `test-env`, verify worker ownership, straight RGBA including alpha, same-allocation UI import, byte accounting, exact retention boundary, partial attachment, cancellation/suspension and failure handling. Run the full application library and binary tests. Verify normal and controlled-failure startup on desktop against the frozen PW6 and Scribe pixels, including changing activity on the deliberately slow fixture.
2. Use an isolated, network-disabled X11 Scribe desktop. Before either warmup, let A materialize a fresh offline demonstration Shelf and exit normally. Copy that closed synthetic seed independently for each process, without sharing writable database files. Seed creation is not a timing sample and need not reproduce the historical Kindle seed. Time **natural** startup: no artificial preparation delay, no startup capture that forces an extra scene. One warmup per arm, then six alternating AB/BA pairs. Keep every attempt and any observer failure. The slow feedback/failure fixtures are separate, not timing samples.
3. Use a single host monotonic clock per case. Report the first observed loading scene, worker prepared-state timestamp, UI receipt, software ready, and first observed complete reference Shelf in the process's own window. Bracket external image transitions with the start of the last nonmatching observation and the return of the first matching one. Compare the entire correct Shelf, not a phase label or a sentinel alone. Report the polling cadence and actual observation uncertainty; neither this nor a screenshot after an exit timer is a Kindle display receipt.
4. Report worker `state-covers` and both UI `attach-covers` spans separately (wall and thread CPU), the inter-batch gap, and each pair's B-minus-A endpoints. To call the desktop Shelf reliably earlier, require correct pixels/behavior throughout, B's conservative first-Shelf upper bound earlier than A's lower bound in at least five of the six pairs, and an earlier median first-match endpoint in both order groups. A cost transfer, noisy point estimates, or overlapping brackets are not sufficient. In that case preserve A as the default and retain B only as a reproducible experiment. Do not select runs by outcome.
5. A desktop win would qualify B for consideration, not deployment. No physical study can start until the earlier device recovery is explicitly closed and a procedure that preserves the existing production entry, data and peer installations is separately qualified. A future paired native-card study must keep independent positive SEND and same-marker driver-completion endpoints; require both endpoints faster in at least five of six pairs and a paired median driver improvement of at least 100 ms before recommending deployment. The present study does not access the Kindle.

## Desktop protocol frozen before measurement

Place the two measured executables at `control` and `candidate` in a fresh private workspace. Copy `desktop_pairs.py`, `rehearse_x11.py`, and the four frozen `startup-0.png`, `startup-1.png`, `final-x11.png`, and `final.png` Scribe normal candidate images from `docs/uiux/baselines/2026-11-17-startup/raw/scribe/candidate/normal/` to `references/` (the scripts belong at the workspace root). Run the following on the verification host, with `WORK` set to that private workspace. The mock draws a changing splash, then a misleading matching Shelf corner, then the full reference. It never starts either application.

```sh
unshare --net /opt/kindle-toolchain/ubuntu-run "$WORK" xvfb-run -a -s '-screen 0 1860x2480x24 -nolisten tcp' python3 -B rehearse_x11.py
unshare --net /opt/kindle-toolchain/ubuntu-run "$WORK" python3 -B desktop_pairs.py --prepare-seed
unshare --net /opt/kindle-toolchain/ubuntu-run "$WORK" python3 -B desktop_pairs.py
```

Seed preparation is a separate A process with a new data directory, `--demo --offline --screen shelf`, normal exit and identical logical Shelf. After retirement, checkpoint and close the synthetic SQLite database and reject live sidecars or links. Each case then starts from a separate non-hard-linked copy of that same closed seed. Seed preparation is neither a warmup nor a sample. The study does not assume this seed is byte-identical to earlier device fixtures. Keep every failure: never overwrite or replace a case to complete the schedule.

Each process owns a newly created X server and a unique named window in it. The observer verifies its `_NET_WM_PID` and 1860 × 2480 geometry and reads that drawable, not the root. A frozen loading-title crop identifies the first observed feedback (the indicator crop is checked separately); this is not the first complete frame submission. A cheap Shelf corner **rejects** a mismatch but cannot certify a match: positive observations compare all RGB pixels of an entire XGetImage to the frozen X11 image, ignoring the fourth padding byte of each depth-24 pixel. Time a request immediately before sending it and on its return, before pixel comparison. The first complete observation must return at or after software ready and follow a known non-Shelf sample; a request spanning readiness is bracketed, not timestamped at an invented point. A later confirmation must also match. Desktop `--capture` checks the final logical pixels *after* the endpoint, not first-presentation time. Both arms use identical tracing, polling, comparison and capture. The 4 ms polling target is not a guaranteed resolution: report the actual last-negative-start to first-positive-return interval per process. Subtract same-clock process entries for cross-process comparisons; do not subtract absolute monotonic timestamps across arms.

## Independent format admission (v2)

The original admission (v1) stopped in `a00` at its first application-window read: it required the same depth-24 XImage as the successful mock. No warmup completed and no measured pair ran. The original failed admission is not restarted or combined with another. It was followed by an **untimed, A-only** [format qualification](x11-layout-qualification.json) using [qualify_x11.py](qualify_x11.py) in a separate workspace. The application window has TrueColor visual `0x40`, depth 32, little-endian 32 bits per pixel and the same three RGB masks as the depth-24 mock; the full-width stride is 7,440 bytes. At the complete Shelf, selecting the RGB planes returned a fourth byte of 0; selecting all planes returned 255. Ignoring the fourth channel, both full-window RGB comparisons, the visible X11 root crop and the independent final logical image matched their respective frozen references exactly. This is format qualification, not an endpoint timing.

The only v2 timing-observer change admits that specific layout with depth 24 **or 32** and reports the observed tuple on failure. The [minimal observer patch](observer-v1-to-v2.patch) reversed on `test-env` to reproduce the original v1 observer byte-for-byte (`patch --reverse -o replayed-v1.py desktop_pairs.py < observer-v1-to-v2.patch`). The mock additionally rejects unsupported depth, word size, channel masks and stride. All clocks, pixel requirements, scheduling, exclusions, decision thresholds and binaries remain unchanged. V2 uses a new private workspace and its **own** A preconditioning run (37 closed demo files); it starts from two new warmups followed by six AB/BA pairs and does not reuse any earlier attempt as a sample.
