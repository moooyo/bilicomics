# Interactive Shelf: desktop baseline protocol

## Question and scope

Measure the first **presented and responsive Shelf**, not software Ready or the last cover, using the [startup contract](../../STARTUP_AND_SLEEP.md#primary-startup-metric-interactive-shelf). The desktop observer must see identifiable non-cover Shelf content and then prove that **this same window** responds to an ordinary user action. No change to product behavior is being compared.

On Kindle the origin is release of the normal Library card. No device action is authorized by this protocol. On `test-env` use the observer's `CLOCK_MONOTONIC` immediately before launching the desktop application, not an invented card event. Keep the child's process-entry timestamp separate. A desktop result cannot fill the native-card result column, nor can the historical 6.802 s full-frame timing.

## Inputs and qualification

Use the stock desktop software renderer, one current Release executable, isolated loopback-only networking, a Scribe-sized Xvfb (1860 by 2480) and an ordinary offline, non-demo Shelf. Use the independent [synthetic 20-comic fixture](../startup-direct-png-20261121/FIXTURE.md) and [recency text written by the product](../startup-cache-maintenance-20261121/PROFILE.md); keep signed-in fixture profiles and screenshots private. All measured cases must start from independent copies of the same closed, two-page Shelf with the same initial grid, page and menu state. Let the onboarded fixture's saved `launch=shelf` select the route, without a `--screen` override. Use the ordinary lifecycle log for child identity and the final capture for a semantic check only, with full performance and UI tracing disabled. No artificial cover or worker delay, simulated application action, renderer wake experiment or fixed wall clock in the baseline.

Qualify the observer before the timed sequence. Use regions outside cover tiles and the status clock to identify a populated Shelf: the count/order line with its filter control (`x=80, y=70, w=1692, h=130`) and the first book's title (`96,632,300,50`) at the 2x Scribe geometry. The local action is to **open the Shelf filter menu** at `(1708,136)`. Require the menu's All/current row (`1040,632,716,70`) that was absent before the input; neither a button-pressed highlight nor an arbitrary pixel change is enough. An independent no-input control must remain closed. A separate offline copy with missing covers must still show the same non-cover Shelf evidence and respond to a fresh click. This tests that the observer does not require the cover pixels, not that a slow network or decoder became faster. Keep qualification attempts and failures separate from the timing sample.

## Frozen timing sequence

1. Use one excluded warmup `w00` and six successive measured launches `s01` through `s06`. Every launch gets a fresh process, profile copy and private Xvfb. No substitution, extension or discarding a slow case. Do not start the measured sequence until the visual and input qualifications pass.
2. Observe the actual mapped, viewable application window and verify its ownership and hit target. Before pressing anything, bracket the last nonmatching and first matching non-cover observations. If the first sample already matches, use the launch origin as a conservative lower bound. Earlier title/activity observations are optional secondary data; a missed loading frame must not disqualify an interactive Shelf. Do not wait for a Ready log, a final screenshot, a cover count or a match to the whole window to trigger the probe. Any geometry, pointer-position or root-window checks must be completed before the fresh button press.
3. Use a single normal XTest button press and release on the filter control, not a call to a Slint callback or a scripted app action. Timestamp the requests and synchronizations, then observe the expected filter-menu contents in the same window and verify the resulting local menu state. Record probe and presentation delays separately; do not time another destination screen or call button release alone proof that the app reacted.
4. Report from the same clock: launch origin, external Shelf observation, button down/up and first confirmed response. If available, retain the child's direct semantic event separately with its actual provenance. **The confirmed response gives an upper bound on when this Shelf was interactive**, not an exact transition timestamp; it includes sampling and the probe gesture. Report per-case values, measured medians and ranges. This is a warmed synthetic desktop baseline, not a cover-completion measurement, a comparison with an older run, a physical panel observation or a forecast for the Kindle.

Only retain bounded timing data, window/process attribution, control and fixture checks, not private account files, full application traces or images. Run verification on `test-env`, not on the operator's machine. Clean up this study's private inputs and processes after the independent replay.
