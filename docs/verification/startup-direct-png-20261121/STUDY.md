# Direct decode of warm managed cover PNGs: study design

## Decision to make

Does decoding an eligible managed PNG into the pixel allocation that the UI will keep make a populated, ordinary offline Shelf appear earlier? The previous [worker-copy experiment](../startup-cover-worker-20261121/README.md) only moved the copy and failed its endpoint gate. It is not the control or a source of samples for this experiment.

- **A:** `9175002` plus the three retained catalog source/test inputs (`src/app/catalog.rs`, `src/store.rs`, `src/store/catalog_cache_tests.rs`); the startup cover code is the control restored in the previous round.
- **B:** A plus direct decoding for eligible ordinary managed startup covers. The destination is a straight RGBA `SharedPixelBuffer` imported by the UI. Do not equate eliminating the end-of-decode `Vec`-to-Slint copy with eliminating decoder workspace, buffer initialization, composition or display writes.
- Do not change the ordinary reader/cache writer, data format, Shelf selection/order, animation, worker admission, cancellation, limits, memory accounting, attachment byte/time budgets or display synchronization. Demo, non-target formats and non-startup reads must keep their original behavior. A and B use the same release profile, features, working path and toolchain. Do not add a flag to the shipped application for the comparison.

## Fixture and qualification

Run only on `test-env`; do not use a physical device or a real account. The [fixture](FIXTURE.md) is a small synthetic ordinary catalog with enough distinct cached static RGBA8 PNGs for multiple Scribe Shelf pages. Fixtures and samplers run in private directories and network namespaces without external connectivity. Each timed launch uses `--offline`, no `--demo`, no artificial preparation delay, and its own copy of an already closed, independently qualified profile. Never export session material, a writable database, or cover contents from that profile as measurement records.

A plain guest is a **negative control**: even if its database contains members, the signed-out Shelf must not qualify as a visible grid. For the primary comparison, use a test-only identity from an in-process fixture adapter via the application's normal validation and private persistence, never a real login or a change to the authentication gate. First qualify A outside timing: assert the Shelf route, complete page count, independent cover markers, actual X11 and logical reference images. Qualify B against those references. An empty screen, placeholder grid, Store page or login prompt is not a Shelf endpoint. If these conditions cannot be met, explicitly report the missing endpoint rather than relabeling another route.

Control the displayed wall-clock minute identically in both application processes and when forming references. Do not mask the clock or any pixels. If a process-local realtime shim is needed, qualify it before timing: process and observer monotonic time and thread CPU clocks must still advance normally. Do not change the host clock. Keep reference generation, negative controls, slow-animation/failure fixtures and clock checks out of the samples. See the [desktop protocol](PROTOCOL.md) for the actual process, grid and timing checks.

## Gates

1. **Correctness first.** On `test-env` check the writer-compatible PNG path, including nonopaque straight RGBA, cached dimensions, bytes and allocation identity from preparation to UI; check fallback equivalence, malformed input, resource boundaries and attachment behavior. Run the application library and binary tests and separate PW6/Scribe demo visual regressions for normal startup and controlled failure. The latter are not proof that the new branch ran. Preserve and identify any failed setup or run.
2. **Presentation is the primary endpoint.** Use a fresh private Scribe-sized Xvfb server per process and the [qualified observer](../startup-cover-worker-20261121/PLAN.md#independent-format-admission-v2): same-PID mapped window, entire RGB image exactly equal to the A reference, a preceding mismatch and a subsequent confirming match. Record bounds from the start of the last negative observation to the return of the first matching read, relative to that process's monotonic entry. Verify the independent final logical image. Never substitute `ui_ready`, cover decode time, a corner sample or a screenshot after an exit timer for this endpoint.
3. **Fixed schedule and adoption threshold.** Exclude one warmup of each arm; run six measured pairs in AB, BA, AB, BA, AB, BA order. Keep slow and failed attempts; do not replace them or extend a close result. Require all correctness checks, B's upper endpoint strictly before A's lower endpoint in at least **five of six** pairs, and negative median paired first-observation changes in **both** order groups. Otherwise keep A as the default. Archive B independently, even if it is not selected.
4. **Explain the mechanism separately.** Report worker `state-covers` wall/thread CPU, all UI `attach-covers` wall/thread CPU, combined measured worker + attachment CPU, publication/consumption, software ready, polling/bracket uncertainty and first confirmed Shelf observations. A savings on these two threads alone is not a startup gain. If the desktop gate passes, this is a candidate for further study, not deployment or a claim about a Kindle's display driver, optical completion, or live accounts.
