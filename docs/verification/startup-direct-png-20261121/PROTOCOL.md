# Ordinary offline Shelf desktop protocol

This procedure is specific to the direct-PNG experiment in [STUDY.md](STUDY.md). It does not import any timing samples, demo catalog data or finished Shelf reference from the worker-copy experiment. It reuses that experiment's qualified RGB sampler and the existing, static Scribe splash title/activity reference only.

## Preconditioning and admission

1. Use a private, mode-0700 directory on `test-env` mounted as `/work` by `unshare --net /opt/kindle-toolchain/ubuntu-run`. The only network interface must be loopback. Copy the closed release binaries from their separately documented A/B build outputs to `control` and `candidate`; compare each copy directly with its source. Use `desktop_pairs.py` from the worker-copy study and place the frozen Scribe `startup-0.png` in `/work/references/`. Neither is a measured launch. Compile the application-only clock shim with `cc -shared -fPIC -O2 -Wall -Wextra -Werror fixed_wall.c -ldl -o fixed-wall.so` and run `python3 -B check_wall.py`. Never preload the observer, X server, helper, or shell. Do not mask the clock or change host time.
2. `python3 -B ordinary_pairs.py bootstrap` starts only the control, with an empty private ordinary data directory, `--offline --screen shelf --device scribe`, and observes its exit and Xvfb retirement. It then checkpoints the schema. `python3 -B ordinary_pairs.py make-seed` creates the strictly synthetic data via `make_fixture.py` and the separate qualified `seed-profile` helper. The helper uses the production cache encoder **before** the signed-out negative is copied. The second helper invocation supplies an in-memory synthetic identity and uses normal session validation and private persistence only on the positive seed. No real login, online request, downloaded comic, existing data or credential file is an input. Do not export the seed or its session, logs, images, catalog, or final UI dump.
3. Before any B timing, qualify A on a new Xvfb for each setup. `reference` obtains two agreeing full-window X11 samples after ordinary readiness, a matching independent visible-root crop, and a separate application logical snapshot. `negative` uses the independently copied, **identical catalog and cover bytes** without a session: same shelf route, populated resources and page count must not falsely qualify. Both X11 and logical images must reject the expected cover codes in the negative. Its logical sign-in panel (physical rectangle `320,740` to `1540,1700`) must also be nonblank and exactly match the actual empty ordinary control's sign-in panel. Positive references must show ten distinct, correctly ordered codes. Record setup failures without promoting them to timed trials. `check-a` and `check-b` exercise the natural observer and each arm's logical comparison against the same frozen ordinary A references. Do not use either qualification launch as a warmup or measured sample.
4. The marker oracle derives coordinates from the Scribe grid, not from either application's output: 2 physical pixels per logical pixel, five columns, `48` logical left margin, `21` horizontal gap, `150 × 200` tiles, first cover top `32+72+4`, second row `292` logical pixels later. Project the fixture's five opaque code centers through the centered, cover-fit `148 × 198` image interior. For each `5 × 5` physical patch all channels must match the dark or light input level within eight levels; placeholders, unrecognized colors and ambiguous marks are invalid. This interprets which distinct cover is really in each A reference. The timed result still requires an **exact comparison of every visible RGB pixel** to that reference.

## Timed comparison

- Start `python3 -B ordinary_pairs.py trial` only once, after qualification and explicit admission. Order: `a00 b00` (excluded), `a01 b01 b02 a02 a03 b03 b04 a04 a05 b05 b06 a06` (six retained pairs). Use new independent data copies and homes, a fresh `1860 × 2480 × 24` Xvfb, software Winit and scale 2 per launch. Do not drop slow samples, replace failures or extend the run. There is no `--demo`, artificial preparation delay or startup capture. The independent final capture uses `--capture final.png --exit-after-ms 800`. Record and stop on a failed case.
- Match the mapped normal application's title `BiliComics` (not the demo title), full window geometry, and `_NET_WM_PID`. Explicitly verify that the process executable is the selected binary via `/proc/PID/exe`. Use the previously qualified TrueColor, 32-bpp BGRX-to-RGB projection of the owned window. Ignore only the unused fourth storage byte. A splash-title match and its initial activity pixels must be seen. A small-region rejection may establish a negative observation, **never** a positive endpoint. `XGetImage` of the entire window must match the frozen A X11 RGB, followed by another exact full-window frame after at least 80 ms. Verify the separately captured final logical image exactly against its own A reference.
- The presentation interval is `[start of previous nonmatch, return of first full match]`, relative to the application's actual monotonic entry, without assuming that samples are instantaneous. Intervals may cross UI readiness. Record both observation bounds, readiness, prepare/publish/consume order, worker cover costs, both UI attachment spans, activity, cadence and sampling cost. All clocks used for timing are real monotonic/thread clocks. The realtime shim does not change application code or the observer clock. Raw records and closed results are reviewed privately on the worker; subsequently remove disposable application output and retain only scoped measurements.
- Require a normal offline Shelf, grid, page 1/2; no `state-demo-*` performance spans; exactly ten ready covers/5,324,800 bytes; the normal worker `state-covers` success; two UI `attach-covers` spans (`partial`, `success`). Pass only if at least five of the six measured pairs have B upper < A lower **and** the median paired first-observed upper endpoint improves in both order groups. Faster worker, UI or ready alone is insufficient. No real-account, Kindle driver, panel or physical-completion result is implied.

## Reproducible, restricted output

Run `python3 -B close_replay.py /work/trial /work/export` only on a complete ordinary trial. It reconstructs both the pair tables and the independently maintained stage-cost summary from the original records, writes explicit field projections, repeats both comparisons, packs only named members, then unpacks them into a new directory and repeats both comparisons again. No input database, session, environment, paths from the application, PNG, cover URLs, UI model, raw logs or binaries are archive members. To replay a retained archive on the verification worker, extract it in a fresh private directory and run `python3 -B summarize_pairs.py /work/extracted/trial` and `python3 -B stage_costs.py /work/extracted/trial --route shelf --ready-covers 10`. `summarize_pairs.py` is the unchanged table renderer from the previous study; these data are not from that study.
