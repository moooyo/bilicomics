# Scope and fixed engineering comparison

Keep every live native-read permission check. Each check samples mutable markers and process ancestry. Removing one changes which transient mismatches may be detected, even if the two observations are close in time. Do not weaken the display capture, freshness checks or wake behavior to obtain a benchmark.

Instead compare two ways to parse the immutable bytes already read by `Writer::process`. A is the shipping `Vec` collection of the stat tail. B advances an iterator through the 20 fields needed to validate process state, parent, group, session and birth. Both keep the original byte bound, whole-record UTF-8 check, `comm` framing, expected PID comparison, length-before-numeric-validation rule, and numeric parsers. Root-owned file checks, `read_link`, all `/proc` and marker reads and their ordering remain untouched in the shipping source. This is a research-only prototype.

On `test-env` use a private Linux toolchain workspace. `prepare.py SOURCE_ROOT OUTPUT` extracts the relevant stock source and its locked error-library version and refuses ambiguous boundaries. Compile the two no-inline functions into the same release executable (`cargo build --release --locked --offline -j1` after generating its private offline lockfile); test the real Linux record and synthetic cases with `setsid -w cargo test --release --locked --offline -j1 -- --test-threads=1`. Launch the benchmark from a child shell with `setsid -w` as well: the subject process must have a positive parent, group and session inside the PID namespace, as a shipping native-read descendant would. No external account, full firmware or device is involved. Only raw record length and field count may leave the process, not its content or PID.

The benchmark snapshots its own legitimate `/proc/self/stat` exactly once before warmup. It then does no I/O inside any timed block. Each arm repeatedly parses that same immutable byte slice 262,144 times, consuming the returned identities with `black_box`. Exclude the first A then B warmup. Keep all 12 successive measured pairs, alternating AB/BA from AB, without replacements. Report elapsed monotonic nanoseconds per record, the median of pairwise B-minus-A differences, both sequence groups, win count and range. These are warm x86-64 CPU-path wall times, not ARM, not complete `Writer::process`, not a native Library timing, and not directly subtracted from the 410 ms display-query envelope. Multiplying by independently observed shipping parse counts produces only a host-cost projection, not a measurement of saved startup time.
