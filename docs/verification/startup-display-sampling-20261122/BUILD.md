# Engineering executable and off-device guard verification

The full Linux host and static ARMv7 release executables were built from the same frozen application source with the [four-file measurement overlay](OVERLAY.md), not a replacement sampler or a test `cfg`. All other compilation inputs matched the base bytes. The shipping JPEG worker matched the installed ZIP member byte for byte; its seven relevant worker and codec sources were unchanged. There was no change to the installed application during qualification. See the [build receipt](engineering-build.json) and [separate ARM/QEMU guard receipt](arm-qualification.json).

| Check | Observation | Boundary |
| --- | --- | --- |
| Host product, Kindle feature, no desktop backend | 225,338,384-byte application built with Rust 1.99.1; real Scribe and PW6 helper invocations without scoped permission refused | Host machine code and command line, not native hardware. The [separate successful product fixture](product_fixture/) supplied synthetic hardware inputs. |
| ARM product | 74,428,464-byte static little-endian ARM hard-float executable; `bilicomics 0.1.25` | Rust 1.99.1, cargo-zigbuild 0.24.0, Zig 0.15.2, offline release. The independently qualified JPEG worker is 426,672 bytes. |
| Actual `qemu-arm` helper, Scribe and PW6 | Both original `--capture-native-display --kindle --device <profile>` invocations rejected the missing native-read directory (exit 1) with the observation selector explicitly enabled | No stdout payload, no cost sidecar, no real framebuffer or input endpoint. No device-specific time was measured. |
| Actual `qemu-arm` normal application, Scribe and PW6 | Both rejected missing owned native-launcher snapshots (exit 1). Only the two expected Shelf trace header/footer records appeared | No Shelf draw, SEND or driver completion. The missing sidecar is not an observation of zero cost. |

Both builds used the shared `ubuntu-run --build` lock, a private target on a size-limited tmpfs, one Cargo job pinned to one CPU, no incremental compilation, isolated networking and the production dependency lock. Each successful ELF was streamed from the compilation namespace, compared against the build product before the namespace exited, and compared again before publication. The ARM scope's soft memory limit was raised twice after observing sustained per-scope memory throttling and verifying aggregate headroom; the hard scope limit and host-wide memory, swap and root-space reserves stayed unchanged. The failed preliminary attempts, scoped limits and sampled resource use are retained in [engineering-build.json](engineering-build.json). The host runtime, build target and intermediate copies were removed after qualification. The engineering ARM application and worker copies were kept for the three physical visits, then removed from the build workspace after all three releases and the result archive were verified. The qualification receipts were preserved.
