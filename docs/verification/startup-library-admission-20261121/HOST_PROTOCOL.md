# Host Library preflight A/B

Freeze two independent blocks. In each, exclude A and B warmups, then measure six adjacent pairs: AB, BA, AB, BA, AB, BA. A is the unchanged production launcher; B removes the redundant Library-parent check only. A host block passes with at least five faster B visits in the six pairs and a median paired B−A of at most −1 ms. Both blocks must pass to recommend a physical experiment on this mechanism. No new pair or block replaces a missing visit, unfavorable result, or busy host. These limits are not the physical performance gate.

Use the Linux `test-env` Ubuntu runtime. Within each block both arms run the actual `/bin/sh launch.sh --library` path, direct `setsid` worker and production preflight commands from the same fixture paths. The success path uses a synthetic Scribe allowlist row, a synthetic firmware file and `/dev/null` for the three character-device predicates. It does not open a framebuffer. Only paths and a stop at the original pre-lock boundary differ from each real launcher. A common shell builtin at that point writes its PID, parent PID and validated profile/firmware to a private FIFO. No lock, application or downstream service runs. Clean-log/font directories and executable/script bytes are already present for both timed arms; neither filesystem caches nor host scheduling are controlled. The `usleep` command lookup is satisfied without introducing a sleep; no signals are sent during measurement.

On the same host monotonic clock, record from immediately before spawning the ordinary Library parent until the waiting observer reads the detached worker's receipt. Verification and final process wait are outside that interval. This includes host shell startup, scheduling and observer wake latency. It is **not** an instrumented card release, first Shelf renderer return, accepted SEND, driver receipt, or optical result. Keep all intervals and missing-endpoint markers; do not scale this host timing to a Kindle.

Outside the timing blocks, separate PATH delegates count the profile lookup, firmware lookup, allowlist lookup and log/font directory preparation per process. They always delegate to the corresponding real Linux utilities. The ordinary and refused configuration cases must pass their exact sequences and preserve the waited worker's exit status. Tool call counts exclude shell builtins and are not a complete syscall profile. A `setsid` hierarchy, original `wait` logic, and independent no-service checks remain part of the existing full launcher regression suite.

From the study directory inside the test container, run `python3 -B -m unittest -v test_bench_admission.py`. Materialize B into `/work/research-candidate/launch.sh` from the frozen stock input as described in [the offline procedure](NATIVE.md#off-device-preparation). Run `python3 -IB bench_admission.py --baseline /work/control/launch.sh --candidate /work/research-candidate/launch.sh --output /work/host-admission-result.json`. Use a fresh result path. The default packaging launcher is A; do not use that path as B. The benchmark exits successfully for a valid negative result; inspect `passes_both_host_gates` rather than treating process success as a speedup.
